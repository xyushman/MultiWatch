## Directory Purposes

**`src/components/`:**

- Purpose: Presentation layer containing all visual interface components.
- Contains: Single File Components (`.vue`) utilizing `<script setup>`, scoped `<style>`, and standard accessibility attributes.
- Key files: `VideoGrid.vue`, `VideoPanel.vue`, `AppHeader.vue`.

**`src/composables/`:**

- Purpose: Headless reactive business logic, platform integrations, and browser API bindings.
- Contains: ES modules exporting composable functions following the `use*` naming convention.
- Key files: `useEmbedFactory.js`, `useKeepAwake.js`, `useResume.js`, `useCloudSync.js`.

**`src/stores/`:**

- Purpose: Central application state and persistent session orchestration.
- Contains: Pinia store definitions.
- Key files: `videos.js`.

**`server/`:**

- Purpose: Lightweight, zero-dependency Node.js server for local and containerized hosting.
- Contains: Native `node:http` request handling, MIME static serving, and JSON file/Upstash storage.
- Key files: `server/index.js`, `server/store.js`.

**`api/`:**

- Purpose: Serverless deployment entry points (specifically for Vercel).
- Contains: Serverless functions consuming shared server logic.
- Key files: `api/state.js`.

**`scripts/`:**

- Purpose: Host environment automation, background playback safeguards, and proxy test runners.
- Contains: PowerShell scripts and Windows batch wrappers.
- Key files: `scripts/start-multiwatch.ps1`, `scripts/start-multiwatch.cmd`.

## Key File Locations

**Entry Points:**

- `src/main.js`: Main client application bootstrap.
- `index.html`: Vite HTML entry point.
- `server/index.js`: Standalone server entry point.
- `api/state.js`: Serverless handler entry point.
- `scripts/start-multiwatch.ps1`: Chromium headless/unattended launcher entry point.

**Configuration:**

- `package.json`: Project manifest and NPM run scripts.
- `vite.config.js`: Vite dev server, chunking, and proxy settings.
- `vercel.json`: Vercel hosting rules and function timeouts.

**Core Logic:**

- `src/stores/videos.js`: Primary state, persistence, and stream array operations.
- `src/composables/useEmbedFactory.js`: URL parsing and embed link synthesis.
- `src/composables/useKeepAwake.js`: Wake Lock and silent audio watchdog.
- `server/store.js`: Safe atomic JSON file and Redis state storage.

**Testing:**

- Currently not configured (no dedicated test directory).

## Naming Conventions

**Files:**

- Vue Components: PascalCase with `.vue` extension (e.g., `VideoPanel.vue`, `AppHeader.vue`).
- Composables: camelCase starting with `use` and `.js` extension (e.g., `useKeepAwake.js`).
- State Stores: camelCase naming the resource domain (e.g., `videos.js`).
- Scripts: kebab-case with `.ps1` or `.cmd` extension (e.g., `start-multiwatch.ps1`).
- CSS Styles: kebab-case with `.css` extension (e.g., `main.css`).

**Directories:**

- Plural, lowercase naming for code categorization (e.g., `components`, `composables`, `stores`, `scripts`).

## Where to Add New Code

**New Video Platform Support:**

- Add platform metadata entry (`label`, `color`) to `PLATFORM_META` in `src/stores/videos.js`.
- Add parser strategy to `PARSERS` object in `src/composables/useEmbedFactory.js` specifying `detect()`, `parse()`, and `buildEmbedUrl()`.
- Update regex in `isValidSourceId` in `src/stores/videos.js`.

**New UI Feature or Control:**

- Header actions: Add button and event emission in `src/components/AppHeader.vue`.
- Panel controls: Add button and listener in `src/components/VideoPanel.vue`.
- Settings controls: Add section to `src/components/AppSettings.vue`.

**New Composable / Browser API Integration:**

- Create new file `src/composables/use[Feature].js`.
- Export reactive refs and an `init()` / teardown function.
- Wire into `src/App.vue` or relevant components.

**New Server Endpoint:**

- In standalone mode: Add route handler in `server/index.js:108`.
- In Vercel serverless mode: Add new handler in `api/[endpoint].js`.

## Special Directories

**`data/`:**

- Purpose: Stores local JSON runtime database (`state.json`).
- Generated: File is dynamically created at runtime by `server/store.js`.
- Committed: Yes, initial template is committed, but runtime updates can be overwritten.

**`dist/`:**

- Purpose: Contains output of Vite build.
- Generated: Yes, produced via `npm run build`.
- Committed: Tracked in git for immediate static previewing, though ignored by default in standard templates.
